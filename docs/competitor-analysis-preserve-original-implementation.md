# تطبيق تقرير تحليل المنافسين — نهج Preserve + Enhance

الفرع: `feature/competitor-analysis-preserve-original`

## المبدأ

لا يتم استبدال المشاهد السينمائية أو المعاينات أو المكونات الأصلية. كل تحسين جديد يجب أن يؤدي واحدة من أربع وظائف:

1. توجيه القرار قبل المشهد.
2. تفسير قيمة المشهد بعده.
3. إضافة معلومات تجارية/تشغيلية مفقودة.
4. ربط الصفحة بمسار آخر دون كسر هويتها.

## الحكم التنفيذي من التقرير

- ابتكار تك منصة أم، وليست متجر خدمات سلة ولا موقع ثيم واحد.
- النتائج والأهداف قبل الأسماء التقنية.
- الخدمات تظهر بوضوح تجاري قريب من المتاجر دون ازدحام marketplace.
- صفحات مستقلة للمنصات.
- ثراء منتج مستقل بصفحة قرار كاملة.
- الدعم والتوثيق والاستمرار جزء من المنتج.
- لا ادعاءات أو أرقام أو شعارات غير موثقة.
- نموذج طلب منظم هو المسار الأساسي، وواتساب مساند فقط.
- Mobile-first وRTL-first.

## Design System

- Premium Editorial-Tech RTL.
- Dark experience في الرئيسية وصفحات المنتج.
- مكونات شفافة ومحدودة فوق المشاهد، لا تدرج على كل عنصر.
- الحركة في نقاط القرار فقط مع احترام `prefers-reduced-motion`.
- شبكات Responsive تتحول 4 → 2 → 1.
- حالات Focus وARIA للفلاتر والقرارات التفاعلية.

## بيانات لا يجوز اختلاقها

- أسعار الخدمات.
- مدد تنفيذ رقمية.
- سعر ثراء.
- عدد العملاء أو المبيعات.
- نسب التحويل أو النمو.
- شعارات أو أسماء عملاء.
- تقييمات.
- روابط شراء/ديمو غير رسمية.

## شروط الدمج إلى main

1. اختبار الصفحة الرئيسية Desktop + 1024 + 768 + 430 + 390 + 360.
2. اختبار ثراء بنفس المقاسات مع Preview/Modal/Sticky CTA.
3. اختبار الخدمات والبحث والفلاتر بلوحة المفاتيح.
4. فحص عدم وجود overflow أفقي.
5. فحص RTL وFocus وEscape وMega Menu.
6. فحص جميع الروابط الداخلية.
7. التحقق من عدم ظهور أي TODO أو قناة تواصل وهمية في UI.
8. اعتماد بيانات ثراء والتواصل أو إبقاؤها مخفية/معطلة.
9. قياس الأداء بعد التحميل الفعلي للصفحات.
